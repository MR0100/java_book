observability-stack/ — Metrics + tracing for the url-shortener

examples/k8s-manifests/observability-stack

Wires the app into a metrics-and-tracing pipeline: Prometheus scrapes its Micrometer metrics, alert rules watch the golden signals, and an OpenTelemetry Collector fans traces out to a tracing backend.

Backing topics: L4/C10 (observability) and lab-06 (distributed tracing).

Files#

File Kind / API Demonstrates
servicemonitor.yaml ServiceMonitor · monitoring.coreos.com/v1 Declarative Prometheus scrape of /actuator/prometheus.
prometheusrule.yaml PrometheusRule · monitoring.coreos.com/v1 Golden-signal alerts (errors, p95 latency, heap saturation, target-down).
otel-collector-configmap.yaml ConfigMap · v1 The Collector pipeline: OTLP receivers → batch/limit processors → Tempo/Jaeger exporters.
otel-collector-deployment.yaml Namespace+SA+Deployment+Service · v1/apps/v1 Runs the Collector as a hardened gateway with a stable OTLP endpoint.

The two pillars here#

Metrics (Prometheus + Micrometer)#

Spring Boot + micrometer-registry-prometheus exposes /actuator/prometheus. The ServiceMonitor tells the prometheus-operator to scrape it — no prometheus.yml edits, no scrape annotations. Watch out: the ServiceMonitor/PrometheusRule release: label must match your Prometheus's serviceMonitorSelector/ruleSelector, or they are silently ignored (the #1 "why isn't it scraping?" gotcha — see the inline comment).

Tracing (OpenTelemetry Collector → Tempo/Jaeger)#

url-shortener (OTel Java agent / Micrometer Tracing, OTLP)
        │  OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector.observability:4317
        ▼
OTel Collector  ──(otlp)──►  Grafana Tempo   (or Jaeger)
        │
        └─► Grafana queries Tempo for traces; correlates with Prometheus
            metrics and Loki logs via shared trace/span IDs.

To emit traces from the app, run it with the OpenTelemetry Java agent:

-javaagent:/otel/opentelemetry-javaagent.jar
OTEL_SERVICE_NAME=url-shortener
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector.observability.svc.cluster.local:4317
OTEL_TRACES_EXPORTER=otlp

Grafana / Tempo / Jaeger#

  • Grafana — the single pane of glass: dashboards over Prometheus (metrics) and Tempo (traces), with exemplars linking a latency spike straight to the trace that caused it.
  • Tempo — Grafana's trace store; OTLP-native, cheap (object storage), pairs naturally with the Collector's otlp/tempo exporter (the default here).
  • Jaeger — the classic alternative; also speaks OTLP (≥ v1.35). Switch by uncommenting the otlp/jaeger exporter in the ConfigMap and adding it to the traces pipeline.

kube-prometheus-stack bundles Prometheus, Alertmanager, and Grafana; add Tempo via the grafana/tempo (or tempo-distributed) Helm chart.

Apply#

bash
# Collector first (creates the `observability` namespace).
kubectl apply -f otel-collector-configmap.yaml
kubectl apply -f otel-collector-deployment.yaml

# Metrics scrape + alerts (require the prometheus-operator CRDs to exist).
kubectl apply -f servicemonitor.yaml
kubectl apply -f prometheusrule.yaml

# Confirm Prometheus discovered the target:
#   Prometheus UI → Status → Targets → expect job="url-shortener" UP.
kubectl -n observability rollout status deploy/otel-collector

Prerequisites & substitutions#

  • prometheus-operator CRDs (ServiceMonitor, PrometheusRule) installed — e.g. via kube-prometheus-stack. Without them the two monitoring manifests won't even validate against the API server.
  • Match the release: label to YOUR Prometheus release name.
  • Substitute the Tempo/Jaeger endpoint in otel-collector-configmap.yaml.
  • Pin the Collector image to a digest in prod (the manifest pins a version tag for readability).
  • Scraping inside a strict-mTLS mesh: if PeerAuthentication is STRICT, either keep the Collector namespace out of the mesh (done here) and scrape the app's merged sidecar metrics port (15020), or give Prometheus the Istio certs. Plain scheme: http to 8080 works only when the app port is excluded from mTLS.

otel-collector-configmap.yaml#

yaml
# =============================================================================
# OpenTelemetry Collector configuration (ConfigMap)
# -----------------------------------------------------------------------------
# Backing topics: L4/C10 (observability) + lab-06 (distributed tracing).
#
# The Collector is a vendor-neutral pipeline: receivers ingest telemetry,
# processors batch/enrich it, exporters ship it to a backend. Your Spring Boot
# app (instrumented with the OpenTelemetry Java agent or Micrometer Tracing +
# OTLP) sends spans to this Collector over OTLP, and the Collector forwards them
# to a tracing backend (Tempo / Jaeger).
#
# Running a Collector (rather than exporting straight from the app) decouples
# the app from the backend: swap Jaeger for Tempo by editing THIS file, not
# every service. It also centralizes batching, retry, and tail sampling.
# =============================================================================
apiVersion: v1
kind: ConfigMap
metadata:
  name: otel-collector-config
  namespace: observability
  labels:
    app.kubernetes.io/name: otel-collector
    app.kubernetes.io/part-of: observability-stack
data:
  # The Collector reads this YAML document as its config file (mounted at
  # /etc/otelcol-contrib/config.yaml by the Deployment).
  config.yaml: |
    # ----- RECEIVERS: how telemetry gets IN -----
    receivers:
      otlp:
        protocols:
          grpc:
            endpoint: 0.0.0.0:4317   # OTLP/gRPC — the default the OTel Java
                                     # agent uses (OTEL_EXPORTER_OTLP_ENDPOINT).
          http:
            endpoint: 0.0.0.0:4318   # OTLP/HTTP — for SDKs/agents using HTTP.

    # ----- PROCESSORS: batch, limit, enrich -----
    processors:
      batch:
        # Batch spans before export — far fewer, larger requests to the backend.
        timeout: 5s
        send_batch_size: 512
      memory_limiter:
        # Backpressure so the Collector can't OOM under a span flood. Must be the
        # FIRST processor in each pipeline. check_interval gates how often it
        # samples memory; limits are absolute (tie to the Deployment's limits).
        check_interval: 1s
        limit_mib: 384
        spike_limit_mib: 128
      resourcedetection:
        # Attach k8s/cloud resource attributes (cluster, node, region) so traces
        # are queryable by infra dimensions.
        detectors: [env, system]
        timeout: 5s

    # ----- EXPORTERS: where telemetry goes OUT -----
    exporters:
      # --- Traces -> Grafana Tempo (OTLP-native). SUBSTITUTE the endpoint. ---
      otlp/tempo:
        endpoint: tempo.observability.svc.cluster.local:4317
        tls:
          insecure: true            # In-cluster plaintext; enable TLS in prod.
      # --- Alternative trace backend: Jaeger (also speaks OTLP since v1.35). ---
      # otlp/jaeger:
      #   endpoint: jaeger-collector.observability.svc.cluster.local:4317
      #   tls:
      #     insecure: true
      # --- Debug exporter: prints to the Collector log; handy when bringing the
      #     pipeline up. Remove or set verbosity: basic in prod. ---
      debug:
        verbosity: normal

    # ----- EXTENSIONS: health & profiling endpoints -----
    extensions:
      health_check:
        endpoint: 0.0.0.0:13133     # The Deployment's probes hit this.

    # ----- SERVICE: wire receivers -> processors -> exporters into pipelines -----
    service:
      extensions: [health_check]
      pipelines:
        traces:
          receivers: [otlp]
          processors: [memory_limiter, resourcedetection, batch]
          exporters: [otlp/tempo, debug]
        # A metrics pipeline is optional here: app metrics already flow to
        # Prometheus via the ServiceMonitor. Enable this only if you prefer to
        # funnel metrics through the Collector too.
        # metrics:
        #   receivers: [otlp]
        #   processors: [memory_limiter, batch]
        #   exporters: [debug]
      telemetry:
        logs:
          level: info

otel-collector-deployment.yaml#

yaml
# =============================================================================
# OpenTelemetry Collector — Deployment + Service (+ Namespace)
# -----------------------------------------------------------------------------
# Backing topics: L4/C10 (observability) + lab-06 (distributed tracing).
#
# Runs the OTel Collector ("contrib" distro, which bundles the broadest set of
# receivers/exporters) as a central gateway. Apps send OTLP here; it forwards to
# the tracing backend per otel-collector-configmap.yaml. The Service gives apps
# a stable endpoint: otel-collector.observability.svc.cluster.local:4317.
#
# NOTE: this is the "manual" Deployment form for teaching. In production you'd
# typically install the OpenTelemetry Operator and use an `OpenTelemetryCollector`
# custom resource (which generates this Deployment for you) — see the README.
# Several documents below, separated by `---`.
# =============================================================================
apiVersion: v1
kind: Namespace
metadata:
  name: observability
  labels:
    app.kubernetes.io/part-of: observability-stack
    # Keep the Collector OUT of the Istio mesh: it's infra, and meshing it adds
    # mTLS/port-shifting complexity to the OTLP ingest path.
    istio-injection: disabled
---
apiVersion: v1
kind: ServiceAccount
metadata:
  name: otel-collector
  namespace: observability
  labels:
    app.kubernetes.io/name: otel-collector
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: otel-collector
  namespace: observability
  labels:
    app.kubernetes.io/name: otel-collector
    app.kubernetes.io/component: telemetry-gateway
    app.kubernetes.io/part-of: observability-stack
spec:
  replicas: 2                  # 2 for availability; the Collector is stateless,
                              # so scale horizontally with load.
  selector:
    matchLabels:
      app.kubernetes.io/name: otel-collector
  template:
    metadata:
      labels:
        app.kubernetes.io/name: otel-collector
        app.kubernetes.io/component: telemetry-gateway
        app.kubernetes.io/part-of: observability-stack
    spec:
      serviceAccountName: otel-collector
      automountServiceAccountToken: false
      securityContext:
        runAsNonRoot: true     # Same hardening discipline as the app (L4/C08/T19).
        runAsUser: 10001
        runAsGroup: 10001
        fsGroup: 10001
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: otel-collector
          # Pin to a concrete version (and in prod, a digest). The contrib image
          # carries the otlp receivers and tempo/jaeger exporters used above.
          image: otel/opentelemetry-collector-contrib:0.110.0
          imagePullPolicy: IfNotPresent
          args:
            - "--config=/etc/otelcol-contrib/config.yaml"
          securityContext:
            allowPrivilegeEscalation: false
            readOnlyRootFilesystem: true   # Config is read-only-mounted; the
                                          # Collector needs no writable root.
            capabilities:
              drop:
                - ALL
          ports:
            - name: otlp-grpc
              containerPort: 4317
              protocol: TCP
            - name: otlp-http
              containerPort: 4318
              protocol: TCP
            - name: healthcheck
              containerPort: 13133
              protocol: TCP
          resources:
            requests:
              cpu: "100m"
              memory: "256Mi"
            limits:
              cpu: "500m"
              # Keep the container limit above the Collector's memory_limiter
              # limit_mib (384) + headroom, so the limiter sheds load before the
              # kernel OOM-kills the pod.
              memory: "512Mi"
          livenessProbe:
            httpGet:
              path: /          # health_check extension serves 200 on / at :13133
              port: healthcheck
            periodSeconds: 15
          readinessProbe:
            httpGet:
              path: /
              port: healthcheck
            periodSeconds: 10
          volumeMounts:
            - name: config
              mountPath: /etc/otelcol-contrib
              readOnly: true
      volumes:
        - name: config
          configMap:
            name: otel-collector-config
            items:
              - key: config.yaml
                path: config.yaml
---
apiVersion: v1
kind: Service
metadata:
  name: otel-collector
  namespace: observability
  labels:
    app.kubernetes.io/name: otel-collector
    app.kubernetes.io/part-of: observability-stack
spec:
  type: ClusterIP
  selector:
    app.kubernetes.io/name: otel-collector
  ports:
    - name: otlp-grpc        # Apps point OTEL_EXPORTER_OTLP_ENDPOINT here:
      port: 4317             #   http://otel-collector.observability:4317
      targetPort: otlp-grpc
      protocol: TCP
    - name: otlp-http
      port: 4318
      targetPort: otlp-http
      protocol: TCP

prometheusrule.yaml#

yaml
# =============================================================================
# PrometheusRule — alerting on the url-shortener's golden signals
# -----------------------------------------------------------------------------
# Another prometheus-operator CRD (monitoring.coreos.com/v1). The operator
# loads these PromQL alert/record rules into Prometheus. Alerts fire to
# Alertmanager (routing to Slack/PagerDuty is configured there, not here).
#
# The rules below follow the GOLDEN SIGNALS (latency, traffic, errors,
# saturation) using the metric names Micrometer exposes for Spring Boot.
# Backing topic: L4/C10 observability.
# =============================================================================
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: url-shortener-alerts
  namespace: url-shortener
  labels:
    app.kubernetes.io/name: url-shortener
    # Same selector-matching caveat as the ServiceMonitor: must match the
    # Prometheus's `ruleSelector` (kube-prometheus-stack uses `release`).
    release: kube-prometheus-stack
    role: alert-rules
spec:
  groups:
    - name: url-shortener.rules
      # How often Prometheus evaluates this group.
      interval: 30s
      rules:
        # ---- ERRORS: 5xx ratio over total requests --------------------------
        - alert: UrlShortenerHighErrorRate
          # 5xx responses as a fraction of all responses, over 5 minutes.
          # http_server_requests_seconds_count is Micrometer's request counter;
          # `status` is the HTTP status label.
          expr: |
            sum(rate(http_server_requests_seconds_count{job="url-shortener",status=~"5.."}[5m]))
              /
            sum(rate(http_server_requests_seconds_count{job="url-shortener"}[5m]))
              > 0.05
          for: 5m                  # Must hold for 5m to fire (debounces blips).
          labels:
            severity: critical
            service: url-shortener
          annotations:
            summary: "url-shortener 5xx error rate > 5% (current: {{ $value | humanizePercentage }})"
            description: "More than 5% of requests are failing with 5xx over the last 5 minutes."
            runbook_url: "https://runbooks.example.com/url-shortener/high-error-rate"
        # ---- LATENCY: p95 request duration ----------------------------------
        - alert: UrlShortenerHighLatencyP95
          # 95th percentile latency from the Micrometer histogram buckets.
          expr: |
            histogram_quantile(0.95,
              sum(rate(http_server_requests_seconds_bucket{job="url-shortener"}[5m])) by (le)
            ) > 0.5
          for: 10m
          labels:
            severity: warning
            service: url-shortener
          annotations:
            summary: "url-shortener p95 latency > 500ms (current: {{ $value }}s)"
            description: "95th-percentile request latency has exceeded 500ms for 10 minutes."
        # ---- SATURATION: JVM heap pressure ----------------------------------
        - alert: UrlShortenerJvmHeapPressure
          # Used heap as a fraction of max heap. jvm_memory_* are Micrometer's
          # JVM gauges; area="heap" filters out non-heap pools.
          expr: |
            sum(jvm_memory_used_bytes{job="url-shortener",area="heap"}) by (pod)
              /
            sum(jvm_memory_max_bytes{job="url-shortener",area="heap"}) by (pod)
              > 0.9
          for: 10m
          labels:
            severity: warning
            service: url-shortener
          annotations:
            summary: "url-shortener pod {{ $labels.pod }} heap > 90%"
            description: "Sustained high heap usage; risk of long GC pauses or OOM. Review -XX:MaxRAMPercentage and the memory limit (L5/C03/T15)."
        # ---- AVAILABILITY: target down --------------------------------------
        - alert: UrlShortenerTargetDown
          # `up` is the synthetic metric Prometheus sets per scrape target.
          expr: up{job="url-shortener"} == 0
          for: 2m
          labels:
            severity: critical
            service: url-shortener
          annotations:
            summary: "url-shortener scrape target down ({{ $labels.instance }})"
            description: "Prometheus cannot scrape this instance — the pod may be crash-looping or the /actuator/prometheus endpoint is unreachable."

servicemonitor.yaml#

yaml
# =============================================================================
# Prometheus ServiceMonitor — scrape the app's /actuator/prometheus
# -----------------------------------------------------------------------------
# Backing topics: L4/C10 (observability) and lab-06 (distributed tracing).
#
# A ServiceMonitor is a Custom Resource from the prometheus-operator (the CRD
# group monitoring.coreos.com/v1, installed by kube-prometheus-stack). Instead
# of editing prometheus.yml, you declare WHICH services to scrape and HOW; the
# operator generates the scrape config. This is the current best-practice
# replacement for prometheus.io/scrape pod annotations.
#
# Spring Boot exposes Prometheus metrics at /actuator/prometheus when the
# `micrometer-registry-prometheus` dependency is present and the endpoint is in
# management.endpoints.web.exposure.include (set in the deployment's ConfigMap).
# =============================================================================
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: url-shortener
  namespace: url-shortener
  labels:
    app.kubernetes.io/name: url-shortener
    app.kubernetes.io/instance: url-shortener
    # CRITICAL: this label must match your Prometheus's `serviceMonitorSelector`.
    # kube-prometheus-stack defaults to selecting ServiceMonitors labelled
    # `release: <helm-release-name>` (commonly `kube-prometheus-stack` or
    # `prometheus`). If your ServiceMonitor is ignored, this label is almost
    # always why — check `kubectl get prometheus -A -o yaml | grep -A5 ServiceMonitorSelector`.
    release: kube-prometheus-stack
spec:
  # Which Services to scrape: those matching these labels...
  selector:
    matchLabels:
      app.kubernetes.io/name: url-shortener
      app.kubernetes.io/instance: url-shortener
  # ...in these namespaces (omit to default to the ServiceMonitor's own ns).
  namespaceSelector:
    matchNames:
      - url-shortener
  endpoints:
    - port: http                 # MUST match the *name* of the Service port
                                 # (service.yaml names it `http`), not the
                                 # number. The operator resolves it.
      path: /actuator/prometheus  # Micrometer's Prometheus scrape endpoint.
      scheme: http                # If you enforce STRICT mTLS in the mesh,
                                 # Prometheus needs the Istio certs or you scrape
                                 # via the merged sidecar metrics port (15020).
                                 # See README "scraping inside a strict mTLS
                                 # mesh".
      interval: 15s               # Scrape every 15s. Balance resolution vs the
                                 # cardinality/storage cost of your metrics.
      scrapeTimeout: 10s
      honorLabels: false
      # Keep label cardinality sane: drop noisy per-URI histogram series that
      # Micrometer can emit, which otherwise blow up Prometheus memory.
      metricRelabelings:
        - sourceLabels: [__name__]
          regex: 'http_server_requests_seconds_bucket'
          action: keep            # Example: keep the bucket series we chart...
        - sourceLabels: [uri]
          regex: '/actuator.*'
          action: drop            # ...but drop self-monitoring actuator URIs.
